# دار — منصة إقامات وحجوزات

نموذج أولي عربي متجاوب لمنصة اكتشاف أماكن الإقامة. الواجهة مبنية حاليًا بـHTML وCSS وJavaScript دون إطار عمل، لتعمل مباشرة على GitHub Pages.

## ما يعمل في النموذج

- واجهة عربية من اليمين إلى اليسار، متجاوبة مع الهاتف وسطح المكتب.
- بطاقات إقامة تجريبية مع صور محلية، تقييمات، وأسعار توضيحية.
- تصفية حسب نوع الإقامة، بحث بالمدينة/الحي، اختيار عدد الضيوف، وفرز حسب السعر أو التقييم.
- مفضلة مؤقتة أثناء الجلسة، ونموذج تفاصيل/طلب حجز تجريبي.
- لا يُرسل النموذج بيانات ولا ينفّذ دفعًا. تسجيل الدخول وإضافة العقار يعرضان تنبيهًا بأن الربط لم يُفعّل بعد.

## معاينة محلية

```bash
python3 -m http.server 8000 --directory public
```

ثم افتح `http://localhost:8000`.

## النشر

الموقع داخل `public/`، ويمكن نشره عبر GitHub Pages باختيار المجلد `/public` كمصدر إن كان إعداد المستودع يدعم ذلك، أو تحديث إعداد Pages/سير العمل إلى نشر محتوى هذا المجلد. سير عمل Jekyll الموجود تاريخيًا يحتاج مراجعة إعدادات النشر قبل الاعتماد عليه.

## الخطوات التالية لنسخة إنتاجية

1. إنشاء مخطط قاعدة بيانات للعقارات والحجوزات والمستخدمين في Supabase.
2. تفعيل Row Level Security (RLS) وسياسات وصول دقيقة، والتحقق من الصلاحيات قبل أي نشر.
3. ربط تسجيل الدخول بـSupabase Auth، وتحميل العقارات والحجوزات عبر واجهة آمنة.
4. استخدام Storage لإثباتات الدفع فقط إذا كان تدفق العمل يتطلب ذلك، مع سياسات خاصة للملفات.
5. إضافة مزود الدفع الذي يحدده مالك المشروع وتأكيد الدفع عبر Webhooks موثّقة من الخادم.
6. إعداد اختبارات للمدخلات، التواريخ، وصلاحيات المستخدمين قبل إطلاق استقبال حجوزات فعلية.

## إعدادات وأسرار

لا تضع مفاتيح سرية في ملفات الواجهة أو المستودع. متغيرات البيئة المتاحة في بيئة تطوير Manus ليست إعدادًا تلقائيًا لنشر GitHub Pages، كما أن مفتاح Supabase العام المخصص للمتصفح وسياسات RLS يحتاجان إعدادًا صريحًا. لا تُضف مفاتيح `service_role` أو مفاتيح Stripe السرية إلى JavaScript في المتصفح.

## الحالة

هذا نموذج واجهة فقط، ولا يتصل حاليًا بـSupabase أو Claude أو Stripe، ولا ينشئ حجوزات أو مدفوعات حقيقية.
